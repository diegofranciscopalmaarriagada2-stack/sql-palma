DML — Lenguaje de Manipulación de Datos SELECT INSERT UPDATE DELETE

▼
🌍 EN LA VIDA REAL
📖 SELECT = Leer un documento
✍️ INSERT = Llenar un formulario nuevo
✏️ UPDATE = Corregir algo ya escrito
🗑️ DELETE = Borrar una fila del papel
💻 EN SQL (tabla: CLIENTES)
SELECT * FROM CLIENTES
INSERT INTO CLIENTES VALUES(...)
UPDATE CLIENTES SET nombre='Ana'
DELETE FROM CLIENTES WHERE id=5
SELECT — Ver datos
-- Ver TODOS los datos de la tabla USUARIOS SELECT * FROM USUARIO; -- Ver solo algunas columnas SELECT NOMBRE, FECHA_NAC FROM CLIENTES; -- Alias (renombrar columnas para mostrar) SELECT PRECIO AS "Precio Actual", PRECIO * 1.1 AS "Con 10% más" FROM PRODUCTOS;
💡SELECT * significa "dame TODAS las columnas". Es como decir: "muéstrame todo". El FROM dice de qué tabla. El AS le cambia el nombre visual a la columna (solo para mostrar, no cambia nada en la BD).
INSERT — Insertar datos
-- Formato LARGO (especificas las columnas) INSERT INTO PROVEEDORES (NIF, NOMBRE, DIRECCION) VALUES ('1-1', 'ANA', 'SU CASA'); -- Formato CORTO (respeta el orden de columnas de la tabla) INSERT INTO PROVEEDORES VALUES ('2-2', 'JUAN', 'SU DEPTO'); -- Fecha con función TO_DATE INSERT INTO CLIENTES VALUES('1-2','SALAS','ROSA','SU CALLE',to_date('01-01-2000','DD/MM/YYYY'));
⚠️ ¡Importante! Los textos (CHAR, VARCHAR, DATE) van con comillas simples 'así'. Los números van sin comillas directamente: 1000.
✅ Integridad referencial: Si una tabla tiene FK (clave foránea), primero inserta en la tabla "padre" (sin FK) y luego en la "hija". Ej: primero PROVEEDORES, después PRODUCTOS.
UPDATE — Modificar datos existentes
-- Cambiar el sueldo de UN usuario específico UPDATE USUARIO SET USUAR_SUELDOMES = 3500 WHERE USUAR_ID = 2; -- Aumentar la fecha de publicación en 1 día (libros >100 pag e id<6) UPDATE LIBRO SET FECHA_PUBLIC = FECHA_PUBLIC + 1 WHERE CANT_PAG > 100 AND IDLIBRO < 6; -- Eliminar (poner NULL) el IDEDIT de libros específicos UPDATE LIBRO SET IDEDIT = NULL WHERE IDLIBRO IN (2,3,5,9,10);
🚨 ¡Sin WHERE el UPDATE cambia TODOS los registros! Siempre usa WHERE para apuntar a quién quieres modificar, a menos que quieras cambiar todo.
DELETE — Eliminar registros
-- Eliminar libros publicados entre 2001 y 2005 DELETE FROM LIBRO WHERE EXTRACT(YEAR FROM FECHA_PUBLIC) BETWEEN 2001 AND 2005; -- También funciona con DATE DELETE FROM LIBRO WHERE FECHA_PUBLIC BETWEEN DATE '2001-01-01' AND DATE '2005-12-31'; -- Eliminar con OR (menos de 20 O más de 300 páginas) DELETE FROM LIBRO WHERE CANT_PAG < 20 OR CANT_PAG > 300; -- Eliminar TODO (vaciar tabla sin destruirla) DELETE FROM LIBRO;

DDL — Lenguaje de Definición de Datos CREATE ALTER DROP TRUNCATE

▼
🏗️DDL es para crear la estructura de la base de datos — es como construir la mesa antes de poner los platos encima. No maneja datos, maneja tablas y columnas.
CREATE TABLE + Constraints
CREATE TABLE EDITORIAL ( IDEDIT INT, NOMEDIT VARCHAR(15), ANYO_FUNDA INT, CONSTRAINT PK_EDITORIAL PRIMARY KEY (IDEDIT) ); CREATE TABLE LIBRO ( IDLIBRO INT, IDEDIT INT, -- FK a EDITORIAL TITULO VARCHAR(20), FECHA_PUBLIC DATE, CANT_PAG INT, CONSTRAINT PK_LIBRO PRIMARY KEY (IDLIBRO), CONSTRAINT FK_EDIT FOREIGN KEY (IDEDIT) REFERENCES EDITORIAL );
Tipo de datoUsoEjemplo
INTNúmero entero42, 1000
VARCHAR(n)Texto variable hasta n caracteres'Hola'
CHAR(n)Texto fijo de n caracteres'1-1'
DATEFecha'2025-01-15'
✅ DROP vs DELETE: DROP elimina la TABLA ENTERA (estructura + datos). DELETE elimina solo FILAS (la tabla sigue existiendo).

✅ CASCADE CONSTRAINTS: Permite borrar una tabla aunque otras tablas hagan referencia a ella: DROP TABLE EDITORIAL CASCADE CONSTRAINTS;

TCL — Control de Transacciones COMMIT ROLLBACK SAVEPOINT

▼
🌍 ANALOGÍA — Juego de videojuego
💾 COMMIT = Guardar partida (cambio permanente)
↩️ ROLLBACK = Cargar partida anterior (deshacer)
📍 SAVEPOINT = Punto de control intermedio
💻 EN SQL
DELETE FROM VENTAS;
-- ¡Ups! Me equivoqué
ROLLBACK; -- ¡Vuelve!
COMMIT; -- Guardar
🚨 ROLLBACK NO funciona después de COMMIT. Una vez que haces COMMIT, los cambios son permanentes. TRUNCATE tampoco se puede revertir con ROLLBACK.
✅ Siempre haz un SELECT antes de un DELETE o UPDATE para verificar qué vas a eliminar/modificar. Luego haz COMMIT si está correcto, ROLLBACK si te equivocaste.

Filtros y Condiciones WHERE BETWEEN LIKE IN ORDER BY

▼
Ejemplos de filtros
-- BETWEEN: entre un rango (¡incluye los extremos!) DELETE FROM LIBRO WHERE CANT_PAG BETWEEN 20 AND 300; -- equivale a: WHERE CANT_PAG >= 20 AND CANT_PAG <= 300 -- LIKE: búsqueda por patrón -- % = cualquier cosa _ = exactamente 1 caracter SELECT * FROM PRODUCTOS WHERE NOMBRE LIKE 'P%'; -- empieza con P SELECT * FROM PROVEEDORES WHERE NOMBRE LIKE '%D%'; -- contiene D -- IN: lista de valores específicos UPDATE LIBRO SET IDEDIT = NULL WHERE IDLIBRO IN (2,3,5,9,10); -- ORDER BY: ordenar SELECT * FROM CLIENTES ORDER BY FECHA_NAC ASC; -- del más viejo al más joven SELECT * FROM CLIENTES ORDER BY APELLIDO DESC; -- Z a A
OperadorSignificado¿Incluye el límite?
>Mayor que❌ No
<Menor que❌ No
>=Mayor o igual✅ Sí
<=Menor o igual✅ Sí
BETWEEN A AND BEntre A y B✅ Sí (ambos)

Manejo de Fechas en SQL/Oracle

▼
Fechas
-- Forma estándar en Oracle/SQL WHERE FECHA_PUBLIC BETWEEN DATE '2001-01-01' AND DATE '2005-12-31' -- Insertar con formato específico to_date('01-01-2000', 'DD/MM/YYYY') -- Sumar días a una fecha (ejercicio 5 de la prueba) UPDATE LIBRO SET FECHA_PUBLIC = FECHA_PUBLIC + 1 WHERE CANT_PAG > 100 AND IDLIBRO < 6; -- En Oracle, DATE + 1 = mañana (suma 1 día)
💡 En Oracle, puedes sumar o restar números a una fecha: FECHA + 1 = el día siguiente, FECHA - 7 = hace una semana.
